## 1. 한눈에 보기

- **형태:** 의존성 없는 단일 `index.html` (HTML + CSS + JS가 한 파일). 빌드 시스템 없음.
- **하는 일:** 한국인 이름 데이터와 여러 "패턴"을 조합해 인스타그램 ID 후보를 만들고, 이름·소개글을 붙여 표/CSV로 출력.
- **핵심 아이디어:** ID를 완전 무작위로 만들지 않고 *이름을 잘게 쪼개 숫자·구분자와 섞는* 식으로 실제 한국 사용자들이 쓰는 모양을 흉내 냄. 같은 브라우저에서는 중복이 나오지 않도록 기록을 저장.
- **규모:** 한 번에 최대 20,000개. 20,000개 생성에 Node.js 기준 약 2~3초.

## 4. 생성 파이프라인

ID 하나는 `generateOne(usedSet)`이 만듭니다. 최대 300번까지 다시 시도합니다.

```
성(fam) 무작위 선택
→ 전략(strategy) 선택 (pickStrategy)        // 최근 2회 쓴 전략은 제외, 가중치 적용
→ 이름(given) 선택 (namePool: 성별 필터 적용)
→ 전략 함수 실행 → { id, label }
→ 검증: isValidId(id) && 중복 아님 && 길이 통과 확률(LEN_ACCEPT)
→ 통과하면 label 다듬기(pickLabel, formatLabel), bio 생성(genBio)
→ { id, label, bio, ts } 반환
```

`generateBatch()`는 이것을 요청 개수만큼 반복하되 **500개마다 `setTimeout`으로 화면에 양보**해서
진행률을 갱신하고 `Stop`을 받을 수 있게 합니다. 끝나면 기록에 합쳐 저장하고 표를 그립니다.

길이 통과 확률(`LEN_ACCEPT`)은 짧은 ID를 더 잘 통과시켜 길이 분포를 실제 계정에 가깝게 합니다.

| 길이 | 6 | 7 | 8 | 9 | 10 | 11 |
|---|---|---|---|---|---|---|
| 통과 확률 | 1 | 1 | 1 | 0.9 | 0.4 | 0.25 |

## 5. ID 생성 전략 9가지

| # | 함수 | 방식 | 예시 |
|---|---|---|---|
| 1 | `stratFragmented` | 이름을 2~3조각으로 쪼개고 생년 숫자를 끼워 넣음 | `e.un_ji9.8`, `seo_yeon98` |
| 2 | `stratKeyboard` | 한글 이름을 두벌식 자판 알파벳으로 바꾸고 숫자를 붙임 | `rlasdw` + 숫자 |
| 3 | `stratEngNick` | 영어 단어 + 이름 조각 + 숫자 | `happy._.jini9844` |
| 4 | `stratKrWord` | 한국어 단어(로마자) + 숫자/이름 힌트 | `gamseong_9.8` |
| 5 | `stratFrame` | `oo`, `xx` 같은 프레임으로 감쌈 | `oo.kimzzang.ii` |
| 6 | `stratAesthetic` | 감성 단어(`daily`, `studio`…) + 이니셜 + 숫자 | `ilsang.l3e.mj98` |
| 7 | `stratSyllableMix` | 이름 음절을 구분자로 엮음 | `seo_._yeon.98` |
| 8 | `stratNickname` | 닉네임 기반 (가중치 0.4 → 전체의 약 4.8%) | `bbungbbung972` |
| 9 | `stratRandomSyll` | 랜덤 음절 조합. 첫 음절은 항상 성, 마지막은 이름 첫 음절 | `ki_ban_na97` (형태 예시) |

공통으로 쓰는 장치:

- **`birthNum()`** 항상 4자리 이상 숫자를 만듭니다 (연도 2자리 + 월, 또는 + 일). 2자리 숫자만 붙이면 너무 흔한 ID가 되기 때문입니다.
- **`fragNum()`** 숫자를 `.` 또는 `_`로 한 번 쪼갭니다 (`9804` → `98.04`).
- **`leet()`** 25% 확률로 글자 하나를 숫자로 바꿉니다 (`o`→`0`, `i`→`1`, `e`→`3`, `a`→`4`, `l`→`1`).
- **구분자 풀** `SEPS_GENERAL`/`SEPS_CUTE` 등. `._.` 같은 화려한 조합은 비중을 낮춰 둡니다.

## 6. 검증 규칙

`isValidId(id)`가 모든 조건을 확인합니다.

- 길이 6~11
- 정규식 `^[a-z0-9._]+$`
- `..` 없음, 맨 앞 `.` 없음, 맨 뒤 `.` 없음
- 구분자(`.` `_`) 3개 이하
- `isComplexEnough`: 구분자가 없고 숫자가 3자리 이하이며 7자 미만이면 거부, 구분자도 숫자도 없는 순수 알파벳도 거부

`cleanId()`는 허용 문자 외 제거, 연속 점 정리, `___` 이상은 `__`로, 앞뒤 점 제거를 합니다.
**길이는 자르지 않습니다.** 11자를 넘으면 `isValidId`가 거부하고 다시 만듭니다 (이유는 [12장](#12-설계-결정과-이유)).

## 7. 이름 · 성별 · 소개글

### 성별 필터
- `namePool()`: `g === 선택한 성별` 또는 `g === "n"`(중성)인 이름만.
- `nickPool()`: `g`가 없는 닉네임(성별 무관) + 해당 성별 + 중성.
- `wordPool()`: 이름 표기용 단어 중 `KR_WORD_G`에 등록된 성별 단어(`공주`, `소녀`, `예쁜이`, `요정` = 여, `소년` = 남)를 반대 성별에서 제외.
- 중성으로 둔 이름: 시온, 가람, 하람, 이루, 소울, 율, 지민, 수현, 지원, 유진, 지수, 정원, 수민, 누리, 하온, 하랑 (16개).
- 현재 이름 분포: 여 96 / 남 67 / 중성 16. 닉네임: 여 전용 30 / 남 전용 14 / 무관 53.

### 이름 표기(`pickLabel`)
`stratNickname` 외의 전략은 다음 확률로 표기를 고릅니다.

| 확률 | 결과 |
|---|---|
| 20% | 이름만 (`서연`) |
| 10% | 영문 표기 — 60% `Seoyeon Kim`, 25% `Kim Seoyeon`, 15% `Seoyeon` |
| 10% | 랜덤 닉네임 (`nickPool()` + `wordPool()`) |
| 60% | 성+이름 (`김서연`) |

그다음 `formatLabel`이 5% 확률로 이모지를 하나 붙입니다.

### 소개글(`genBio`)
- 55% 확률로 생성, 45%는 빈 값.
- 생성 시 60%는 `BIOS_STATIC`(50개) 중 하나, 40%는 `[지역] / [내용] [이모지]` 조합(`genBioDynamic`).
- 이모지 포함 비율은 약 30% (측정값, 이름 이모지 포함 시 약 35%).

## 8. 저장소(localStorage)와 CSV

| 키 | 내용 |
|---|---|
| `kr_ig_ids_v5` | 생성 기록. `[id, label, bio, ts]` 배열의 JSON (용량 절약을 위해 객체가 아닌 배열) |
| `kr_ig_gender` | 성별 필터 선택값 (`all` / `f` / `m`) |

- 버전을 올릴 때(`v3`→`v4`→`v5`) 이전 키는 읽지 않습니다. 형식이 바뀌면 키를 올리세요.
- `saveHistory()` 반환값: `"ok"`, `"reset"`(용량 초과 → 비우고 최신 5,000개만 저장), `"failed"`(그것도 실패 → 저장 안 됨).
  UI는 이 값에 따라 안내 문구를 붙입니다.
- 2만 개 기록은 약 0.86M 글자.
- `exportCSV("batch" | "all")`: 현재 배치 또는 전체 기록을 CSV로. 형식은 README 참고.

## 9. 테스트

자동 테스트 프레임워크는 없고, 브라우저 없이 돌리는 점검 스크립트가 있습니다.

```bash
node scripts/smoke-test.js          # 기본 20,000개 × (All, Female, Male)
node scripts/smoke-test.js 1000     # 개수 지정
```

`index.html`의 `<script>`를 그대로 꺼내 가짜 `document`/`localStorage`와 함께 실행합니다. 확인하는 것:

- 모든 ID가 `isValidId`를 통과하는지, 중복이 없는지
- 평균 길이, bio 비율, 이모지 비율, 영문 이름 비율
- 성별 필터에서 반대 성별 전용 단어가 새지 않는지

문제가 있으면 `PROBLEMS: ...`를 출력하고 종료 코드 1로 끝납니다. 실행 예 (2만 개):

```
[all] 20000 ids in 2552ms | mean length 9.20 | bio 55.2% | emoji 34.8% | romanized names 9.2% | ok
```

**이 스크립트가 확인하지 못하는 것:** 브라우저 화면(레이아웃, 스크롤, 모바일 표시), 클립보드와 파일 다운로드 동작,
실제 localStorage 용량 한도. 이런 부분은 브라우저에서 직접 확인해야 합니다.

## 11. 수정하는 방법

| 하고 싶은 일 | 위치 |
|---|---|
| 이름·닉네임·단어 추가 | 해당 배열에 항목 추가. 이름은 `g`(성별)를 꼭 지정. 닉네임 `g`가 없으면 성별 무관 |
| 성별이 갈리는 단어 표시 | `KR_WORD_G` |
| 이름 표기 비율 변경 | `pickLabel` 안의 `r < 0.20` 등 |
| 소개글 추가/비율 변경 | `BIOS_STATIC`, `BIO_*`, `genBio` |
| ID 길이 범위 변경 | `isValidId`, `LEN_ACCEPT` |
| 전략 비중 변경 | `STRATEGY_WEIGHTS` (순서는 `STRATEGIES`와 같음) |
| 새 전략 추가 | `strat…(fam, given)` 함수를 만들어 `{ id, label }` 반환 → `STRATEGIES`와 `STRATEGY_WEIGHTS` 끝에 추가 |
| 최대 개수/화면 표시 수 | `MAX_COUNT`, `RENDER_LIMIT`, 입력칸 `max` 속성 (둘 다 바꿔야 함) |
| 저장 형식 변경 | `loadHistory`/`saveHistory`와 함께 `STORAGE_KEY` 버전을 올림 |

수정 후에는 `node scripts/smoke-test.js`를 돌리고, 브라우저에서 한 번 열어 화면을 확인하세요.

## 12. 설계 결정과 이유

- **ID를 11자에서 자르지 않는다.** 초기에는 `slice(0, 11)`로 잘랐는데, 2만 개를 측정해 보니 ID의 84%가 11자로 몰리고 이름·숫자가 잘려 나갔습니다(`byeonye.won`). 지금은 길이 초과를 거부하고 다시 만들어서 길이가 6~11에 고르게 퍼지고 평균은 약 9.2자입니다.
- **단순한 ID를 걸러낸다.** `hama05`, `remon01` 같은 짧고 단순한 ID는 이미 쓰이고 있을 가능성이 거의 100%라는 지적에서 시작했습니다. 2자리 숫자 금지(`birthNum`은 4자리 이상), 자판 변환 전략은 숫자를 항상 붙임, `isComplexEnough` 검사를 둡니다. 단순할수록 유니크하지 않다는 점과 실제 사용자 ID의 모양(평균 8~9자) 사이에서 길이 가중치(`LEN_ACCEPT`)로 절충했습니다.
- **`stratRandomSyll`은 항상 성 + 이름 첫 음절을 넣는다.** 예전에는 무관한 음절만 이어 붙여 `s_jin` → "손도훈"처럼 이름과 ID가 어긋났습니다.
- **성별 필터를 우회하지 않는다.** 예전에는 `stratNickname`과 `stratRandomSyll`이 전체 이름 풀을 써서 남자 필터에 여자 이름이 나왔습니다. 우회를 없애고 닉네임에도 성별(`g`)을 달았습니다.
- **성별이 애매한 이름은 중성으로 둔다.** 지민, 수현, 지원, 유진, 지수처럼 실제로 남녀가 다 쓰는 이름은 중성(`n`)으로 분류해 양쪽 필터에 나옵니다. 민지, 슬기, 하루, 민아, 보민은 여성으로 확정했습니다.
- **닉네임 전략은 약 5%로 제한한다.** 가중치 0.4(나머지 1)이면 전체 9개 중 약 4.8%입니다 (요구: 7% 미만).
- **500개씩 나눠 처리한다.** 2만 개를 한 번에 돌려도 수 초이지만, 화면이 멈추지 않게 하고 진행률·중단을 받으려는 구조입니다.
- **저장은 배열 형식.** 객체 키 이름이 2만 번 반복되는 것을 피해 용량을 줄였습니다.
- **용량 초과 시 리셋.** 저장이 실패하면 생성 버튼이 죽는 대신 기록을 비우고 최신 5,000개만 남겨 계속 쓸 수 있게 했습니다.
- **UI는 영어, 데이터는 한국어.** 외국인도 쓸 수 있게 UI 문구를 영어로 했고, 한국식 ID라는 도구의 성격상 이름·닉네임·소개글은 한국어로 유지했습니다.

## 13. 작업 이력

대화로 진행한 작업을 순서대로 정리한 것입니다.

1. **초기 버전** — 성/이름 데이터와 전략으로 ID를 생성, 중복 방지용 localStorage 기록.
2. **데이터 확장** — 이름·단어 추가, 닉네임 전략과 랜덤 음절 전략 도입.
3. **UX 개선** — 이름의 띄어쓰기와 괄호 제거, 14자 이하 제한, 저장소 리셋 버튼, 최대 개수 500 → 5,000.
4. **단순 ID 문제 수정** — 단순한 ID가 나오는 원인 분석 후 4자리 이상 숫자, 복잡도 검사 도입.
5. **성별 필터** — 여자/남자/전체 버튼. 중성 이름은 양쪽에 포함.
6. **대규모 개편**
   - UI 전체 영문화
   - ID 길이 6~11자
   - 성별 분류 재정리(이름 19개 재분류, 이름·닉네임 추가), 성별 우회 제거
   - 닉네임 전략 비중 제한(7% 미만)
   - bio 생성, 이름 이모지, CSV 컬럼을 `username,name,bio,generated_at`으로 변경
   - 데이터 확장 (이름 약 120 → 179, 닉네임 66 → 97 등)
7. **표 UI** — 결과를 `username | name | bio` 한 줄 표로, 복사 버튼 제거, 기본 개수 500.
8. **20,000개 지원** — 500개씩 나눠 처리, 최대 20,000, 화면은 1,000개만, 용량 초과 대응, 길이 자르기 폐지, 이름 표기 다양화, 헤더 고정·툴팁·모바일 레이아웃, 성별 필터 유지.
9. **마무리 개선** — 이름 표기 비율 조정(이름만 20%, 영문 표기 10%), 성별 단어 필터, CSV 날짜 형식·배치/전체 저장·파일명 개선, Stop 버튼, 짧은 ID 가중치, 재시도 300회.
10. **문서화** — README, 이 문서, 점검 스크립트.

## 14. 알려진 한계 / 앞으로 할 수 있는 것

**한계**

- 실제 인스타그램 계정과의 중복·사용 가능 여부는 알 수 없습니다 (확인하는 기능이 없으며, 자동 조회는 서비스 약관상 권하지 않습니다).
- 이름과 ID의 연관성은 전략마다 다릅니다. `stratKrWord`, `stratFrame`, `stratAesthetic`은 ID에 이름 흔적이 없을 수 있습니다.
- ID의 생년 숫자와 bio의 나이는 맞추지 않습니다.
- bio 정적 문구가 50개뿐이라 반복이 많습니다.
- 기록은 브라우저별이며, 서버나 계정에 저장되지 않습니다.
- 자동화된 단위 테스트와 브라우저 테스트는 없습니다 (점검 스크립트만 있음).

**해 볼 만한 것**

- 성별이 갈리는 `KR_WORDS`를 더 찾아 `KR_WORD_G`에 추가
- bio 문구 확장, 이름/성별에 맞춘 bio
- 이름과 ID의 연관성을 높이는 옵션(전략별 on/off)
- 기록 가져오기(CSV 불러오기)로 다른 브라우저와 중복 검사 공유
- 브라우저 자동화 테스트(화면, 다운로드)
